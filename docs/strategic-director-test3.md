# Strategic Director Test 3: One-Prompt Agent

## Goal

Validate whether REUP.goals can collect business context through one strong
Strategic Director prompt instead of a rigid multi-step JSON pipeline.

The main product bet:

- the model should feel like a live strategic director, not a form;
- backend prepares only useful context and stores conversation history;
- the model decides how to answer naturally;
- structured memory extraction can be moved to a separate background layer later.

## Current Iteration Scope

Implement the first stage of the new architecture behind the existing endpoint:

- `POST /api/v2/strategic-director/messages`

Frontend contract stays compatible:

- backend still returns `assistant_message`;
- backend still returns current memory fields for the UI;
- but the visible answer is generated by a natural text model call, not by a
  JSON-first memory response.

## What Backend Does

For every user message:

1. Save the raw user message.
2. Load current state:
   - recent dialogue;
   - existing snapshot;
   - existing claims;
   - existing documents;
   - existing research agenda;
   - existing communication profile;
   - existing dialogue focus.
3. Retrieve a small set of relevant older messages using lightweight keyword
   search.
4. Build one context pack for the model:
   - latest user message;
   - recent dialogue;
   - relevant older dialogue snippets;
   - existing business memory;
   - product goal.
5. Call OpenAI with one Strategic Director prompt and ask for a normal Russian
   user-facing answer.
6. Save the assistant reply as raw dialogue history.
7. Return the reply to frontend.

## What Backend Does Not Do Yet

This iteration intentionally does not:

- force model output into JSON;
- update claims/documents/snapshot synchronously from the visible chat call;
- build strategy;
- implement full vector store retrieval;
- implement file upload ingestion;
- implement background memory compaction.

These are separate next layers if this test proves the dialogue quality.

## Success Criteria

The test is successful if:

- the chat no longer feels like a typed questionnaire;
- the model responds to the user's actual tone and last message;
- the model does not repeat answered baseline questions;
- the model asks one useful next question or a compact connected block;
- the model can handle launch-stage and mature businesses differently;
- response time is acceptable enough for continued staging tests;
- no 500 is returned when the model is slow.

## Known Tradeoff

Because structured extraction is not performed in the main chat call, memory
documents and claims may not update in this first test. That is expected.

If this version feels materially better, the next step is to add an async
background memory writer:

- extract claims;
- update compact business memory;
- update documents;
- index raw messages/files for retrieval.
